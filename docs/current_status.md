# 当前状态与参考工程差距

## 1. 一句话结论

当前仓库已经完成 **black 平地 MuJoCo + TorchScript 的单机 C++ 行走闭环**，但还不是
`rl_sar + real_robot` 的完整替代品。它保留了必要的数据边界和安全校验，主动舍弃了参考工程
中大量机器人、ROS 版本、SDK 副本、重复策略和调试工具。

按不同目标估算完成度：

| 目标 | 当前完成度 | 说明 |
|---|---:|---|
| black 平地 MuJoCo RL 行走 | 约 90% | 前进和横移闭环完成，仍缺转向、扰动和长时间稳定性验证 |
| black 的 ROS 2 仿真替代 | 约 45% | 缺 ROS 2 适配器、话题、手柄和外部导航命令 |
| black 实机部署 | 约 25% | 缺硬件 RobotIO、IMU、通信、安全监督和部署程序 |
| blackW、机械臂及参考工程全部行为 | 低于 20% | 当前刻意只实现 12 关节 black 平地路径 |

这些比例是功能范围估计，不是代码行数进度。

## 2. 已经具备的闭环

```text
键盘 BaseCommand
    → MotionRuntime
    → 45 维观测 × 6 帧历史
    → TorchScript flat 策略
    → 12 维动作和关节阻抗目标
    → MujocoRobotIO
    → MuJoCo 物理状态
    └──────────────────────────→ 下一控制周期
```

已经实现：

- 12/16 关节固定容量核心帧、单调时间戳、显式控制模式和完整数值校验；
- `RobotIO` 作为 motion 与仿真/硬件之间的唯一边界；
- black 机器人、控制器和 RL 参数的启动期 YAML 加载；
- `Passive → GetUp → Stand → RL Running → GetDown`；
- 与 black himloco 配置一致的观测顺序、6 帧历史、动作缩放、KP/KD；
- 真实 TorchScript 平地和障碍模型参考输出测试；
- MuJoCo 无头测试和官方 Simulate 完整调试界面；
- 真实平地策略的前进方向和横移方向闭环位移测试；
- 观测、推理、动作或命令失败时退出主动 RL 控制。

## 3. 与 rl_sar 的差距

| 能力 | 当前状态 | 是否应该直接复制 |
|---|---|---|
| black flat 单策略推理 | 已完成 | 已按固定数据路径重写 |
| flat/obstacle 运行时切换 | 只有配置和模型，没有切换状态机 | 不复制通用工厂，只增加明确行为 |
| himloco、down、MoE、arm 等策略 | 未接入 | 按实际需求逐个增加 |
| 完整 FSM 和组合按键 | 仅基础运动状态 | 不复制旧 FSM 框架，扩展 MotionRuntime |
| `/cmd_vel` 和手柄输入 | 未实现 | 放入 ROS 2/输入适配器 |
| blackW 16 关节轮足控制 | 未实现 | 复用同一 core，不另复制代码树 |
| 多机器人和第三方 SDK | 未实现 | 只引入目标硬件需要的 SDK |
| CSV、绘图和状态 UI | 仅终端状态和 MuJoCo 面板 | 后续采用低频诊断接口 |

## 4. 与 real_robot 的差距

尚未实现的实机侧能力：

- ROS 2 消息转换、节点、launch、QoS 和服务；
- 串口/CAN/厂商 SDK 对应的硬件 `RobotIO`；
- 电机零点、方向、减速比、扭矩换算和最终执行侧限幅；
- IMU 驱动、VQF 姿态估计和传感器健康状态；
- 急停、通信看门狗、失联阻尼、启动握手和故障锁存；
- 里程计、GapModel、桥梁/赛道场景以及额外噪声、延迟和回差模型；
- blackW、black_with_arm 的模型、配置和执行链路；
- 实机部署、进程监督、日志与回放。

## 5. 推荐补齐顺序

1. 增加转向姿态、扰动和长时间闭环测试，冻结 black flat 行为；
2. 增加 ROS 2 外围适配器，只转换 `BaseCommand`、状态和模式请求；
3. 实现目标 black 硬件的 `RobotIO`、校准和安全监督；
4. 完成仿真—实机状态对比、日志和故障注入；
5. 确认 blackW 的实际需求后，再扩展 16 关节观测和轮控制；
6. 最后按任务接入 obstacle、down、机械臂等额外策略。

这个顺序不会把 `rl_sar` 和 `real_robot` 的历史包袱重新搬回仓库。
